FlushLabs

Systems engineering, game technology, and practical R&D.

I’m Flushwhy — a systems engineer and deep tech founder building software close to the hardware, from developer tools and native game integrations to real-time simulation and local AI.

Building

Fe — Project and release tooling

Developer tooling · Build systems · Distribution

A command-line toolkit for taking small projects from setup to shippable releases. Fe aims to make the practical parts of software delivery easier to understand and repeat, without hiding the underlying tools or locking projects into one ecosystem.

Explore Fe

VideoForge — Video rendering

Media tooling · Rendering pipelines

A video creation and rendering project focused on making the workflow dependable and improving render performance. Current work is centered on fixing render reliability and reducing the time it takes to produce an output.

Explore VideoForge

Playriter — Screenplay editor

Android · Fountain · Document workflows

A screenplay editor built around a proper project format, with Fountain import and export as part of a screenplay-focused writing workflow. The goal is to preserve screenplay structure and presentation instead of treating a script as plain text.

Explore Playriter

Game technology and systems work

GameJolt — Unreal Engine integration

Native C++ · Unreal subsystems · Blueprint API

An Unreal Engine plugin that connects games to the GameJolt API through a native C++ layer and Unreal-friendly subsystem interfaces. It covers player sessions, authentication, trophies, scores, and cloud data.

Explore GameJolt

Real-time simulation and local AI

Physics · Neural approximation · Embedded inference

Experiments in making simulation and machine-learning techniques useful inside real applications. This includes ML-assisted 2D physics, deterministic execution, and research into small models that can run locally on constrained devices rather than depending on a cloud service.

How I work

I care about the distance between an idea and a reliable implementation. That means understanding memory, data movement, latency, build pipelines, and the constraints of the machine an application actually runs on.

I prefer small, understandable systems over layers of abstraction. Measure before optimizing, keep dependencies intentional, and make tools that help people ship real work.

Research notes

The R&D Logs collect experiments, benchmarks, and implementation notes. They include work on random-number quality, network coordinate compression, quantization, and performance-oriented techniques.
